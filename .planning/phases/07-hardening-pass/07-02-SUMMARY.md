### Out-of-Scope Discovery (documented, not fixed — see SCOPE BOUNDARY)

**1. Pre-existing test-environment 301-redirect on every HTTP-client test request**
- **Found during:** Task 2 and Task 3 regression verification (`billing.test_webhooks`, `organizations.tests`)
- **Issue:** `DEBUG=False` in this environment activates `SECURE_SSL_REDIRECT = True` (`Backend/rumi/settings.py:349-351`), causing every `APIClient`/Django test-client request to 301-redirect before reaching the view, regardless of the view's own logic.
- **Evidence it predates this plan:** A baseline `organizations.tests` run captured *before* any Task 3 edit already showed 10/11 failures, all `301 != <expected>`. Re-running after Task 3's changes shows the same 10/11 failures, identical in count and identity — zero regressions from this plan's `actor` kwarg / `log_audit()` additions. `billing.test_webhooks`'s `HandleBillingEventTests` (calling `handle_billing_event()` directly, no HTTP layer) all pass both before and after Task 2's changes; only `DispatchFromPaystackWebhookTests` (HTTP-layer) fails, for the same pre-existing reason.
- **Not fixed:** Changing `SECURE_SSL_REDIRECT`/`DEBUG`/test-settings behavior is outside this plan's `files_modified` list and outside HARD-03's audit-trail scope. Fixing it risks altering unrelated test behavior this plan was never asked to touch.
- **Logged to:** `.planning/phases/07-hardening-pass/deferred-items.md` with full reproduction evidence and a recommendation for a future task.
